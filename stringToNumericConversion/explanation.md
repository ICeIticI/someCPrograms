In this program, the amount of checks the program needed to find each element in both parallel arrays varied. For example, the 'I' numeral is at the very beginning of the numeral array, which is onen so one check is all that's needed. Because the corresponding value of the numeral stored in the other array shares the same exact index number, one check is all that will ever be needed for the other array. On the other hand, any other value will need more checks, such as numerals V, X, L, etc. M is at the very end of the array, stored at index 6, so 7 checks are needed, but one check is all that is needed for the other array after finding the index for the numeral array. The number of checks are different because the program doesn't magically know where each element is, so it has to check through each element to find them. That is, through a for loop, a linear search.

Edge cases have also been considered, tested and mitigated. I've tried all sorts of gibberish input, and none have ever creeped through. The program rejects every input that is not in the roman numerals table, so every other value that can possibly be inputed simply gets rejected. In simple terms, the program runs like a whitelist, so only the invited guests are permitted in the program, that being, the roman numerals. If one or more roman numerals are inputted, and then invalid characters get entered afterwards, the program will, as usual, throw my custom error message and terminate, never finishing.
